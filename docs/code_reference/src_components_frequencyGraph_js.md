# Code Reference: `src/components/frequencyGraph.js`

This file implements the `FrequencyGraph` class, a high-performance interactive HTML5 `<canvas>` component used to visualize frequency responses. It acts as the visual centerpiece of the Neon Equalizer application, rendering the equalizer curve, measurements, target curves, and providing an interactive interface for shaping the sound.

## Architecture and Design

Unlike many web applications that use heavyweight SVG-based charting libraries (like D3.js or Chart.js), `FrequencyGraph` is a custom, zero-dependency, immediate-mode canvas renderer. This design choice guarantees 60fps performance even when recalculating complex IIR filter responses across hundreds of frequencies in real-time.

It handles rendering:
1.  **Grid System**: A logarithmic X-axis (frequency) and linear Y-axis (amplitude/gain).
2.  **Filter Nodes**: Interactive, draggable points representing parametric EQ filters.
3.  **Curves**:
    *   **Measurement**: Headphone frequency response data (e.g., from Squiglink).
    *   **Target**: The desired frequency response curve (e.g., Harman Target).
    *   **Corrected**: The simulated result of applying the current EQ filters to the measurement.
    *   **EQ Total**: The combined frequency response of all active Parametric and Graphic EQ filters.
4.  **Delta Band**: A visual representation of the difference between the measurement and target curves.
5.  **Preference Bounds**: Harman-inspired tolerance bands (an upper and lower bound curve) guiding the user towards an ideal response.
6.  **Spectrum Analyzer Overlay**: Real-time frequency analysis data pulled from a Web Audio API `AnalyserNode`.

## Core Mechanisms

### Coordinate System Conversions
The class maintains an active viewport defined by `viewFreqRange` (default 20Hz-20kHz) and `dbRange` (default ±30dB).
*   `freqToX(freq)` and `xToFreq(x)` map between frequency values and horizontal pixel coordinates using a base-10 logarithmic scale.
*   `dbToY(db)` and `yToDb(y)` map between amplitude values (decibels) and vertical pixel coordinates linearly.

### DSP Integration (`_calcFilterResponse`)
The graph relies entirely on the shared `src/dsp/biquad.js` module. By delegating calculation to `filterGainDb`, the graph guarantees that what the user sees on screen is mathematically identical to what is executed in the audio pipeline and what is generated by the AutoEQ optimizer.

### The Render Loop (`render` and `_draw`)
State changes (like dragging a node or receiving new data) trigger `render()`, which requests an animation frame. The `_draw()` function clears the canvas and redraws all elements in a specific Z-order:
1.  Background gradient
2.  Reference image (if loaded)
3.  Grid and axis labels
4.  Curves (Target, Measurement, Delta Band, Corrected, EQ)
5.  Interactive Nodes
6.  Draw path (if the user is freehand drawing a curve)
7.  Spectrum overlay

### Data Handling and Normalization
When loading data (`setMeasurementData`, `setTargetData`), the graph cleans and sanitizes it using `_sanitizeCurve`. Crucially, it normalizes the SPL (Sound Pressure Level) data to make disparate curves comparable:
*   `normalizeSplData(data)` aligns curves vertically. It supports pinning to a specific frequency (usually 1000Hz, or 500Hz for 5128 rigs) or using an average amplitude over a midrange window.
*   `_smoothCurve(data)` applies 1/N-octave fractional smoothing (e.g., 1/12 octave) to noisy measurement data by binning points into logarithmic bands and averaging them. This is critical for making visual comparisons easier.

### Interactivity
The graph supports rich interactivity natively on the canvas overlay:
*   **Panning & Zooming**: Users can click and drag the background to pan the view, or use the mouse wheel to zoom in on specific frequencies or amplitudes.
*   **Node Dragging**: Mousing over a filter node shows a tooltip. Clicking and dragging modifies the filter's frequency (X-axis) and gain (Y-axis), instantly updating the EQ curve.
*   **Q Adjustment**: Scrolling the mouse wheel while hovering over a node adjusts its Q-factor (bandwidth/sharpness).

### Freehand Draw Mode (`setDrawMode`)
The graph features an innovative mode allowing users to "draw" an EQ shape directly on the canvas using mouse or touch.
*   Points are captured in `_appendDrawPoint` as the user drags.
*   When dragging finishes (`_finishDrawEQ`), `_drawPointsToBands` interpolates the drawn stroke into a set of standard 31-band graphic EQ sliders, effectively converting a freehand shape into actionable equalizer data.

## Compatibility and Integrity
A major feature of the graph is ensuring users don't mix incompatible data (`getCurveCompatibility`). It cross-checks the metadata of the measurement against the target (e.g., preventing a user from optimizing a generic IEC711 IEM measurement against a target designed for the B&K 5128 rig).

## Can we live without it?
No. The graph is the primary visual interface for the Equalizer. It provides the crucial visual feedback needed to tune audio, verify AutoEQ results, and understand the impact of filters.

## Areas for Improvement
*   **Render Optimization**: Currently, `_drawCurves` recalculates the combined response of all filters for every single pixel column on every frame. While fast enough on modern machines, caching the combined response buffer and only invalidating the segment affected by a dragged filter would significantly reduce CPU usage during interactions.
*   **Curve Extrapolation**: If a target curve stops at 10kHz, the graph simply stops drawing it. It could intelligently extrapolate flat or sloped extensions to fill the view bounds.
